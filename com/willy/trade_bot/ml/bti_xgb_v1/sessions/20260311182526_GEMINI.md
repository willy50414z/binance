## 2. Supplementary Recommendations (補充建議)

### A. 模型預測熵 (Output Entropy) 檢查
如果模型預測機率長期塌在 `0.33`，請計算驗證集上的平均預測熵（Mean Prediction Entropy）。
- **High Entropy (接近 1.0)**: 表示模型對所有類別都完全不確定。這通常是特徵與標籤之間缺乏互信息（Mutual Information）的徵兆。
- **Low Entropy but Bias**: 表示模型學到了一個恆定的 Bias（例如永遠猜 Hold）。這通常是類別不平衡或損失函數權重問題。

### B. 空特徵基準測試 (Null Feature Test)
在進行大幅超參數掃描前，建議執行一次「洗牌測試」：將特徵矩陣隨機打亂（Shuffle）後重新訓練。
- 如果打亂後的模型表現（Validation Loss）與原始特徵訓練的模型表現幾乎一致，則說明當前的特徵集對標籤完全沒有解釋力，應該回頭重整特徵工程（Feature Engineering），而不是調整模型或門檻。

### C. 標籤穩定性 (Label Stability) 檢查
當 `lookahead` 從 4 增加到 12 時，標籤的自相關性（Autocorrelation）會顯著增加。
- 建議在掃描 `lookahead` 時，一併輸出標籤的轉移矩陣（Transition Matrix），確認標籤是否因為視界拉長而變得過於平滑或過於雜訊。

### D. 排除特定時段噪音
`best_iteration = 4` 有時是因為 Validation Set 的前段與 Train Set 的末段存在劇烈的 Regime Shift。
- 建議檢查 Validation Set 的起始點是否剛好落在市場極端波動期。

## 4. Final Final Plan (匯總最終執行計畫)

這份計畫整合了 CODEX 的結構化診斷與 GEMINI 的特徵效能驗證：

1. **[Immediate] 執行 Null Feature Test**: 確認原始特徵是否優於隨機噪音。若否，立即暫停後續掃描，回頭優化 `TECHNICAL_INDICATOR_COLUMNS`。
2. **[Diagnostic] 補全報表**: 包含 `candidate_count`、`fallback_status`、`Prediction Entropy` 以及 `Prediction Distribution`。
3. **[Execution] 分層 Threshold 策略**:
   - 診斷模式：`total_trades >= 1`，觀察全域機率分佈。
   - 決策模式：`total_trades >= 5` 且必須橫跨至少 3 個不同的時間區段 (Temporal Diversity)。
4. **[Experiment] Lookahead x ATR Grid**: 在確認特徵有效的前提下，尋找讓 Label Density 最具可學性的標籤組合。
5. **[Refinement] Calibration Comparison**: 僅在 Raw Probability 具備基本 Ranking 能力（AUC > 0.52）時，才進行 Isotonic/Sigmoid 校準。
